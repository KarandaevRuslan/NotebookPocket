# NotebookPocket 0.9.3 — Nexus в демонстрации «Блины»

## Что добавлено

В штатном рецепте появилась карточка «04 / Готовим и изучаем Nexus» после пошаговой инструкции. Нажатия «+ 1 готов», «− 1» и «Начать заново» записывают счётчик через транзакции `nexus.dispatcher.inline`. `Nexus.Handler` вычисляет количество полных порций по два блина. `nexus.observe` передаёт оба значения из Store в Observable Notebook, а зависимая ячейка обновляет счётчики, количество оставшихся блинов и индикатор прогресса. Изменение числа яиц меняет цель, не сбрасывая счётчик.

В карточке есть раздел с короткими пояснениями `Scope`, `Store`, `Dispatcher`, `Handler`, `observe`. Добавлены русская/английская локализации и адаптивные стили. Показан безопасный жизненный цикл `nexus.scope(invalidation)`, `scope.guard` и `scope.cleanup`. Стандартные рецепт, управление шагами и `Pocket.timer` не заменены.

## Обновление уже существующего примера

При следующем запуске приложения штатная миграция обновит **только оригинальные, не изменённые пользователем** версии демонстрации (старую v5 и непосредственно предыдущую v6), сохранив публичные метаданные. Проверяются исходный HTML и SHA-256 каждого ресурса; изменённые HTML/CSS/JSON и незаписанные черновики миграция пропускает. Добавлены эталон исходника и хеши старой v6. Идентификатор `data-state-version="pancakes-v5"` оставлен прежним, чтобы не сбрасывать сохранённые настройки рецепта.

Если пользователь ранее менял HTML или вложения демонстрации, создайте новую инструкцию через команду создания — она получит новую версию образца. Счётчик Nexus хранится только в памяти текущего Preview и при перезапуске обнуляется.

## Установка и проверка

Распакуйте этот ZIP в **корень проекта NotebookPocket** с заменой перечисленных файлов. Это не полный проект: архив содержит только новые/изменённые файлы по сравнению с `NotebookPocket-Nexus-0.1.20(1).zip`.

```powershell
cd web
node --test tests/pancakes-nexus-contract.test.mjs
npm test
cd ..
.\gradlew.bat :app:assembleDebug
```

Web-код не изменялся (менялись встроенные Android assets и тесты), поэтому при уже собранных ранее WebView assets запускать `npm run build` повторно не требуется. Если собираете проект с нуля, сначала выполните `cd web; npm ci; npm run build; cd ..`.
